# 构造函数里调虚函数，多态为什么没生效

在 C++ 里，"调用虚函数"并不总等于"调用派生类的实现"。构造函数和析构函数是两段特殊的窗口：对象还没完全造好，或者已经开始拆了，此时虚机制只认当前这一层。本文用一个最小示例复现这个现象，解释虚表指针在构造过程中如何切换，并给出把初始化逻辑安全挪出构造函数的写法。

## 一段会"说谎"的代码

```cpp
#include <iostream>

struct Base {
    Base() {
        std::cout << "Base::Base\n";
        identify();            // 期望打印 Derived::identify
    }
    virtual ~Base() = default;
    virtual void identify() const { std::cout << "Base::identify\n"; }
};

struct Derived : Base {
    Derived() {
        std::cout << "Derived::Derived\n";
        identify();
    }
    void identify() const override { std::cout << "Derived::identify\n"; }
};

int main() {
    Derived d;
    d.identify();
}
```

输出是：

```text
Base::Base
Base::identify
Derived::Derived
Derived::identify
Derived::identify
```

明明创建的是 `Derived` 对象，基类构造函数里的那次调用却老老实实走了 `Base::identify`。这不是编译器优化过头，也不是虚表损坏，而是语言规则本身如此。

## 虚表指针是按层装上去的

多态对象里通常藏着一个虚表指针（vptr），指向当前类对应的虚函数表。这个指针不是一次性写好的，而是随着构造过程逐层覆盖：

1. 分配内存，对象的动态类型在这段时间里被视为 `Base`；
2. `Base` 构造开始，编译器把 vptr 指向 `Base` 的虚表；
3. 初始化 `Base` 的成员，执行 `Base` 构造函数体；
4. `Derived` 构造开始，vptr 被改写成指向 `Derived` 的虚表；
5. 初始化 `Derived` 的成员，执行 `Derived` 构造函数体。

虚函数调用走的是**当前 vptr**。第 3 步时 vptr 还指向 `Base` 的虚表，自然调不到 `Derived::identify`。标准对此有明确规定：从构造函数（包括成员初始化列表）或析构函数中直接、间接调用虚函数时，解析到的是该构造函数/析构函数所在类中的最终覆盖函数，而不是更派生类里的覆盖版本。

这样做有充分理由。假如 `Base` 构造期间真的调到了 `Derived::identify`，而这个函数访问了 `Derived` 的成员，那些成员此刻还没初始化——读到的是未定义的值。语言宁可让多态"迟到"，也不让你拿到半个对象。

注意，即使在 `Derived` 的构造函数体里，`Base` 的成员也已经初始化完毕、`Derived` 的成员同样已初始化完毕，所以那里调用虚函数会正常分派到 `Derived` 版本；分界线就在当前正在执行的那一层构造函数。

## 析构是对称的

销毁过程正好反过来：`Derived` 析构函数体先执行（此时 vptr 仍指向 `Derived` 的虚表），然后是 `Derived` 成员析构，最后轮到 `Base` 析构函数，vptr 切回 `Base` 的虚表。因此写在 `Base::~Base` 里的虚调用同样只会落到 `Base` 的实现上。

| 阶段 | vptr 指向 | `identify()` 实际调用 | 当前"动态类型" |
| --- | --- | --- | --- |
| `Base` 构造函数体中 | `Base` 虚表 | `Base::identify` | `Base` |
| `Derived` 构造函数体中 | `Derived` 虚表 | `Derived::identify` | `Derived` |
| 构造完成后的普通调用 | `Derived` 虚表 | `Derived::identify` | `Derived` |
| `Derived` 析构函数体中 | `Derived` 虚表 | `Derived::identify` | `Derived` |
| `Base` 析构函数体中 | `Base` 虚表 | `Base::identify` | `Base` |

## 纯虚函数：从"调错"变成"崩溃"

如果基类里那个虚函数是纯虚的，问题会从"输出不对"升级成进程终止：

```cpp
#include <iostream>

struct Renderer {
    Renderer() { draw(); }         // 危险：此刻 draw 还是纯虚
    virtual ~Renderer() = default;
    virtual void draw() = 0;
};

struct Circle : Renderer {
    void draw() override { std::cout << "circle\n"; }
};

int main() { Circle c; }
```

GCC 与 Clang 常见输出是 `pure virtual method called`，紧接着 `terminate called without an active exception`，然后 abort——底层走的是 `__cxa_pure_virtual`。标准把"在构造/析构期间对正在构造的对象做纯虚调用"归为未定义行为，所以不要指望所有编译器都打印这行提示，开 LTO 或内联后表现可能变化。

补充一点：纯虚函数是可以有定义的，例如 `void Renderer::draw() {}`。在构造函数里用限定名 `Renderer::draw();` 显式调用这个定义是合法的，但那就绕过了多态，通常也不是你真正想要的效果。

## this 逃逸：另一种提前触发

不一定非要在构造函数里亲手写虚调用。只要把 `this` 在构造期间交给别人，就可能在同一个窗口里被回调：

```cpp
#include <vector>

struct Listener {
    static inline std::vector<Listener*> registry;
    Listener() { registry.push_back(this); }   // 注册得太早
    virtual ~Listener() = default;
    virtual void onEvent() {}
};

struct Worker : Listener {
    void onEvent() override { /* 用到 Worker 的成员 */ }
};
```

`Listener` 构造期间 `registry` 里已经有了这个指针；若此时有人遍历注册表调用 `onEvent`，走的是 `Listener::onEvent` 而不是 `Worker::onEvent`。修正方式是把注册动作放到构造完成之后，比如用一个显式的 `start()` 或在工厂函数里统一处理。

诊断这类问题可以借助 UBSan 的虚表检查：

```bash
g++ -std=c++20 -fsanitize=undefined -fno-sanitize-recover=all demo.cpp
```

如果在 `Base` 构造函数里写了 `static_cast<Derived*>(this)`，它通常会报出 `downcast of address ... which does not point to an object of type 'Derived'`，正好指向"对象还没成为 Derived"这个事实。

## 把初始化挪出构造函数

需要"构造完成后再按多态方式初始化"时，最稳的做法是显式分两阶段，并用工厂保证不会漏掉第二步：

```cpp
#include <iostream>
#include <memory>
#include <utility>

class Base {
public:
    virtual ~Base() = default;

    void init() { onInit(); }        // 构造之外触发分派

protected:
    virtual void onInit() {}
};

class Derived : public Base {
public:
    explicit Derived(int n) : n_(n) {}

protected:
    void onInit() override { std::cout << "n = " << n_ << "\n"; }

private:
    int n_;
};

template <class T, class... Args>
std::unique_ptr<T> make_ready(Args&&... args) {
    auto p = std::make_unique<T>(std::forward<Args>(args)...);
    p->init();
    return p;
}

int main() { auto d = make_ready<Derived>(42); }
```

此时 `onInit()` 被调用时，`Derived` 的成员已经全部构造完毕，虚调用会如预期落到 `Derived::onInit`。调用方只拿到工厂返回的指针，没有"忘记调 init"的机会。

如果初始化所需的参数本来就知道，更简单的办法是直接在基类构造函数里传值，例如 `Base(std::string label)`，彻底不在构造阶段依赖虚分派。少一层间接，也就少一个时序陷阱。

## 小结

- 构造/析构中的虚调用解析到当前类的最终覆盖函数，不是最派生类的版本。
- 原因是 vptr 按继承层次逐层切换，派生部分在基类构造时尚不存在。
- 构造期间调用纯虚函数属于未定义行为，常见表现是 `pure virtual method called` 后终止。
- `this` 在构造期间被注册或传给回调，会把同样的窗口暴露给间接调用。
- 需要"构造后多态初始化"时，用显式 `init()` 加工厂封装；能传参解决的事，别在构造函数里回调虚函数。
